Training Data, Features, and Labels

What Is a Feature?

A feature is an input variable — one piece of information the model is given to help it make a prediction. Suppose Brian is helping a Rafiki Insights client, a small agrovet supply business, build a model to predict which customers will renew their annual supply contract. Useful features might include: how many months the customer has been with the business, their average monthly order size, the number of support queries they have raised, and which industry sector they belong to. Each of these is a separate clue the model can use.

What Is a Label?

The label is different — it is the answer the model is trying to predict, the known outcome attached to each past example. In the contract-renewal example, the label for each past customer is simply "renewed" or "did not renew". Every row of training data needs both: a set of features describing the situation, and a label recording what actually happened. The model studies many such rows to learn how the features relate to the label, so it can make a prediction when it sees a new customer's features without yet knowing the outcome.

Key Point. Features are the clues, the label is the answer those clues are meant to predict. A model is only ever as good as the training data — accurate, relevant features and correctly recorded labels — that it was built from.

Garbage In, Garbage Out: Why Data Quality Matters

No algorithm, however sophisticated, can make up for poor training data. If the features contain irrelevant or noisy information, if values are missing or wrong, or if the labels themselves were recorded incorrectly, the model will confidently learn the wrong patterns. This is often summarized as "garbage in, garbage out": the quality and relevance of the training data is what determines the quality of the resulting model — not the cleverness of the technique used to build it. Brian always checks a client's data for accuracy and relevance before building anything on top of it.
