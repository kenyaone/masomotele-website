Limits of NLP Tools: Hallucination and Context Loss

1. What "Hallucination" Means

Sometimes an AI chat assistant states something fluently and confidently that is simply wrong or entirely made up. In the field, this is called a hallucination. It might be a fabricated statistic, a report title that doesn't exist, or an incorrect date — delivered in exactly the same confident tone as a correct answer.

This happens because the tool is predicting plausible-sounding text based on learned patterns, not checking a verified database of facts. If there's no strongly-patterned correct answer available from what it learned, it still produces something fluent — and that fluent-sounding answer can simply be wrong. If Brian asks an assistant for "the average small-business loan default rate in Kenya" and gets back a precise-looking percentage, that number may be entirely fabricated, even though it reads convincingly.

2. Losing Track in Long Conversations

These tools only "keep in mind" a limited amount of the recent conversation. In a long back-and-forth, details mentioned much earlier can get dropped, or the tool can end up contradicting something it was told before — not out of dishonesty, but because it is re-generating its reply based on what's still visible to it, not from a lasting memory of everything ever said.

For example, Brian might tell an assistant early in a long session that "the client's fiscal year ends in June." Forty messages later, in the middle of an unrelated request, the assistant might quietly assume a different year-end. That's context loss, not a lie.

3. Brian's Rule: Verify Before It Goes Into a Client Report

Because of both hallucination and context loss, any specific fact, figure, date, or name an AI tool generates needs to be checked against a real, checkable source before Rafiki Insights uses it in client-facing material. The tool is a useful drafting partner — not a verified source of truth.

Key Point. Fluent and confident is not the same as correct. Before anything factual from an AI tool goes into a client report, Brian checks it against a real source first.
