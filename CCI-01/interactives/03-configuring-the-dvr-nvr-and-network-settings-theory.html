Unit 3 · Topic 3.3

Configuring the DVR/NVR and Network Settings

Connecting Cameras to the Recorder

The type of recorder depends on the camera type. Analog cameras connect to a DVR using coax (BNC) cable carrying the video signal, while IP cameras connect to an NVR — usually via a PoE (Power over Ethernet) switch that carries both data and power over a single network cable, cutting down on cabling and separate power supplies.

Dennis always confirms which camera type he is connecting to before assuming the recorder's input type. Mixing them up, like plugging an IP camera's network cable into a DVR's BNC input, simply will not work, and it is a common early mistake.

Basic Network Setup

Once cameras are connected, the recorder itself needs a place on the network. Dennis usually gives the recorder a static IP address rather than leaving it on DHCP — a static address means the recorder's address never changes, so viewing software and remote access settings that point to it keep working.

He connects the recorder to the client's router or switch with an ethernet cable, then accesses its settings menu, or a browser or setup app, to confirm the static IP, subnet, and gateway match the rest of the network.

Port Forwarding and Recording Schedules

For the client to view cameras remotely on a phone away from the site, the router needs port forwarding configured. This tells the router to send specific incoming internet traffic through to the recorder's static IP address on the local network, rather than being blocked at the door.

Dennis also sets the recording schedule to match what the client actually needs — continuous recording for high-priority areas, or motion-triggered recording elsewhere to save storage space — and always changes the recorder's default admin password before switching on remote access.

Key Point. Never enable remote access on a recorder that still has its factory-default password — this is one of the most common ways CCTV systems get broken into online, and it takes two minutes to fix.
