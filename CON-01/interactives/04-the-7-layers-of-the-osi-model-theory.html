The 7 Layers of the OSI Model

1. The 7 layers, top to bottom

LayerNameWhat happens here
7ApplicationThe software the user actually interacts with -- a browser, an email client
6PresentationFormatting and encryption of data, e.g. converting to a common format, TLS encryption
5SessionEstablishing, managing and ending a communication session between two devices
4TransportReliable (TCP) or fast-but-unreliable (UDP) delivery, breaking data into segments
3NetworkLogical addressing (IP addresses) and routing between different networks
2Data LinkPhysical addressing (MAC addresses) and delivery within a single local network
1PhysicalThe actual cables, radio signals and electrical/light pulses carrying raw bits

2. A memory trick

A widely used mnemonic, top to bottom: "All People Seem To Need Data Processing" (Application, Presentation, Session, Transport, Network, Data Link, Physical). Most technicians only ever need to fluently recall layers 1, 2, 3, 4 and 7 day-to-day -- those are the ones that come up constantly in real troubleshooting.

3. Why "which layer?" is a useful diagnostic question

Asking "which layer is this problem actually at?" narrows a vague complaint fast. A cable that is unplugged is a Layer 1 problem. A device with the wrong IP address is a Layer 3 problem. A website that will not load despite a working connection could be a Layer 7 (application/DNS) problem. Each layer has different, specific tools and fixes.

4. A worked example

Sending a web page request involves every layer: the browser (Layer 7) asks for a page, the request gets formatted/encrypted (Layer 6), a session is established with the web server (Layer 5), broken into reliable TCP segments (Layer 4), addressed to the server's IP (Layer 3), given the next hop's MAC address (Layer 2), and finally sent as electrical or light signals down the actual cable (Layer 1). The reply travels back up through all 7 layers in reverse.
