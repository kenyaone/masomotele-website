DHCP and DNS Fundamentals

1. DHCP -- Dynamic Host Configuration Protocol

DHCP automatically assigns IP addresses (and related settings like subnet mask, default gateway and DNS server) to devices joining a network, so nobody has to manually type in an IP address on every device. Without DHCP, every single device would need manual IP configuration -- workable for a handful of devices, completely impractical for a real office.

2. The DHCP process, briefly

When a device joins a network, it broadcasts a request for an address. A DHCP server (usually built into the router, or a dedicated server in larger networks) offers an available address, the device accepts it, and the server acknowledges the assignment -- this whole exchange typically happens in a fraction of a second, invisibly to the user. The address is "leased" for a period of time and typically renewed automatically before it expires.

3. DNS -- Domain Name System

DNS translates human-friendly names (like a website address) into the numeric IP addresses computers actually use to communicate. Without DNS, users would need to memorise numeric addresses for every website and service they use -- DNS is effectively the internet's phone book.

4. Why these two matter so much for troubleshooting

A huge share of "the internet is not working" complaints trace back to one of these two services -- either a device failed to get a working address from DHCP (covered in the earlier Virtual Lab on APIPA addresses), or DNS failed to resolve a name to an address even though the underlying connection is fine (the exact pattern from the OSI layer Virtual Lab earlier in this course). Recognising which of the two is failing narrows troubleshooting dramatically.
