System Hardening Basics

Attack Surface

A system's attack surface is everything an attacker could potentially target — every running service, open port, installed application, and enabled feature. A smaller attack surface simply gives an attacker fewer possible ways in.

Key Point. Hardening is largely about subtraction — removing or disabling anything not actually needed, rather than adding more security tools on top of everything.

Unnecessary Services and Default Accounts

Many systems ship with services enabled and default accounts (sometimes with well-known default passwords) that most deployments never actually use. Disabling unused services and removing/renaming default accounts closes off paths an attacker could otherwise exploit without ever needing a "real" vulnerability.

Closing Unused Ports

A network port left open for a service nobody uses is an unnecessary open door. Auditing which ports are actually required for a system's real function, and closing the rest, reduces the attack surface concretely and measurably.

Secure Defaults vs Convenient Defaults

Many products ship with defaults optimised for easy setup, not maximum security (e.g. a default admin password, or remote management enabled by default). Reviewing and changing insecure-but-convenient defaults is a standard, necessary hardening step before any new system goes into production at SafariPay.
