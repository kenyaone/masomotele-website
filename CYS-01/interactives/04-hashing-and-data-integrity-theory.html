Hashing and Data Integrity

What a Hash Function Does

A hash function takes any input (a file, a password, a message) and produces a fixed-length output ("hash" or "digest"). The same input always produces the same hash, but even a tiny change to the input produces a completely different hash — making hashes ideal for checking whether something has been altered.

Key Point. Hashing is one-way by design — you cannot reverse a hash back into its original input, unlike encryption which is meant to be reversible with the right key.

Storing Password Hashes

SafariPay should never store customer passwords in plain, readable text. Instead, it stores the hash of the password — when a customer logs in, their entered password is hashed again and compared to the stored hash. If SafariPay's database is ever breached, attackers get hashes, not directly usable passwords.

Salting

Without salting (adding a unique random value to each password before hashing), two customers with the identical password would produce identical stored hashes — letting an attacker who cracks one instantly know every other account sharing that password. Salting makes every stored hash unique even for identical passwords.

Key Point. Salting defeats "rainbow table" attacks (precomputed hash lookup tables) and stops identical passwords from producing identical, easily-correlated hashes.
