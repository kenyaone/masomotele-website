Cross-Site Scripting (XSS)

What XSS Is

Cross-Site Scripting (XSS) happens when an attacker manages to inject malicious script into a web page that then runs in another user's browser, in the context of the trusted site — potentially stealing session cookies, redirecting the user, or performing actions as that logged-in user.

Stored vs Reflected XSS

Stored XSS saves the malicious script somewhere persistent (a comment field, a profile name) so it runs for every user who later views that stored content. Reflected XSS requires tricking a specific victim into clicking a crafted link that embeds the malicious script in the request itself, reflected back in that one response.

Key Point. Stored XSS is generally more dangerous — it silently affects every visitor to the compromised content, not just one tricked victim.

Output Encoding

The core defence is output encoding — ensuring any user-supplied content displayed back on a page is treated strictly as text/data, not executable code, by encoding special characters (like < and >) before rendering it in HTML.

Content Security Policy (CSP)

A Content Security Policy is an additional browser-enforced layer that restricts which sources of scripts a page is allowed to run, adding defence even if an XSS flaw somehow slips past output encoding.
