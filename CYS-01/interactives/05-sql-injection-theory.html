SQL Injection

What SQL Injection Is

SQL injection happens when user-supplied input is inserted directly into a database query without proper handling, letting an attacker craft input that changes the query's actual meaning — potentially reading, modifying, or deleting data far beyond what the application intended to expose.

How It Happens

If a login form builds a query like SELECT * FROM users WHERE username = '[input]' by directly inserting raw user text, an attacker typing ' OR '1'='1 as the username can change the query's logic entirely, potentially bypassing the login check altogether.

Key Point. The vulnerability is not that users can type malicious text — it is that the application trusted that text enough to let it change the actual structure of the database command.

Parameterised Queries

The standard, reliable defence is parameterised queries (also called prepared statements) — the query structure and the user's data are kept strictly separate, so user input is always treated as pure data, never as part of the query's logic, no matter what characters it contains.

Input Validation Is Not Enough Alone

Trying to filter out "dangerous-looking" characters from user input can help, but is fragile and easy to bypass with clever encoding or edge cases. Parameterised queries fix the underlying structural problem directly, rather than trying to guess and block every malicious pattern.
