Module 8 · Lesson 8.3

Using AI Assistants Safely for Security Work

Legitimate Uses

Grace can reasonably use an AI assistant to draft a first version of a report section, get a plain-language explanation of an unfamiliar security concept, or help summarise a long, generic log excerpt — genuinely useful time-savers for well-bounded tasks.

Never Paste Sensitive Data

Pasting real customer data, actual credentials, internal vulnerability details, or proprietary SafariPay system information into a general-purpose external AI tool risks that sensitive data being retained, logged, or exposed outside SafariPay's control — an unacceptable risk regardless of how convenient it would be.

Key Point. If Grace would not paste it into a public forum, she should not paste it into a general external AI tool either — the same sensitivity judgement applies.

AI-Suggested Configurations Need Review

An AI assistant might suggest a firewall rule, a script, or a configuration change — but exactly like AI-suggested Excel formulas or code (from the earlier AI units in other courses), these suggestions need expert review before deployment, since they may not correctly account for SafariPay's specific environment.

Company Policy

SafariPay should have (and Grace should follow) a clear policy on which AI tools are approved for security work, what categories of information may never be shared with them, and when human sign-off is required before acting on AI-assisted output.
