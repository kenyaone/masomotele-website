Containers vs Codecs — MP4/MOV vs H.264/H.265

What a Container Actually Is

A container (or "wrapper") is the file format you see in the filename — .mp4, .mov, .avi. It is essentially a box that holds the video track, the audio track, subtitles if any, and metadata like frame rate, all bundled together so a player or editor knows how to unpack them.

The container itself does not describe how the picture data is compressed. Two .mp4 files can use completely different internal compression, and two files with different extensions (.mov vs .mp4) can use the exact same compression inside.

What a Codec Actually Is

A codec (coder-decoder) is the compression method used to shrink the raw video data into a manageable file size, and to decompress it again for playback or editing. H.264 (also called AVC) is the most common codec on phones and the web — it is what CapCut exports by default and what most client phone footage arrives as. H.265 (HEVC) compresses further for the same quality, common on newer iPhones. ProRes is a much lighter-compression, high-quality codec used for professional intermediate editing, common in .mov files from higher-end cameras.

So when Otieno gets a clip, the container tells him what box it arrived in; the codec tells him how tightly the footage inside was actually squeezed.

Real Pairings Otieno Sees

A CapCut export saved as .mp4 is almost always H.264 (or H.265 on some phones) inside. An iPhone clip saved as .mov is usually H.264 or H.265 too — MOV is Apple's native container, but it can hold the same codecs as MP4. Footage exported for professional colour grading as ProRes is nearly always wrapped in .mov, since MP4 does not commonly carry ProRes.

This is why a client can send Otieno a .mov file that opens and edits exactly like an .mp4 one — the container extension alone doesn't tell him the compression, or how heavy the file will be to work with on his phone.

Key Point. Container (MP4/MOV/AVI) = the box the file is wrapped in. Codec (H.264/H.265/ProRes) = how the video data inside is actually compressed. Never assume a file's extension tells you its codec, or that its codec tells you its extension — check both separately before deciding how to handle a client's footage.
