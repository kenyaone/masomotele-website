Forms and Validation

Reading Form Input

JavaScript can read what a user typed into a form field via input.value, and can run this check before the form is actually submitted, catching problems early rather than after a server round-trip.

Client-Side Validation

Checking that a required field is not empty, or that an email field contains an "@", before submission gives the user immediate feedback — but as covered in the caregiving-adjacent lesson on secure coding elsewhere, this is a UX convenience, not a security control.

Key Point. Client-side validation can always be bypassed by a determined user — genuine security-relevant validation must also happen on the server, never only in the browser.

Preventing Default Submission

event.preventDefault() inside a form's submit handler stops the browser's normal full-page-reload submission, letting JavaScript handle the data instead (e.g. sending it via fetch without reloading the page).
